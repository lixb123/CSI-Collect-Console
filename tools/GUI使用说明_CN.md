# ESP CSI 采集工具 GUI 使用说明

适用程序：`tools/esp_csi_tool.py`。

本说明用于连接 ESP32-S3 接收端、接入普通路由器或 ESP32 SoftAP、检查 CSI 是否到达，并保存带实验标签的采集数据。现场安全、人员编号和动作规范见[实验操作手册](../EXPERIMENT_COLLECTION_PROTOCOL_CN.md)。

## 1. 采集前准备

1. 接收端 ESP32-S3 已烧录当前接收端固件，并用可传输数据的 USB 线连接电脑。
2. 发射源准备为普通路由器或 ESP32-S3 SoftAP。两者都作为接收端要连接的 Wi-Fi 接入点使用。
3. 关闭任何占用同一 COM 端口的 `idf.py monitor`、串口助手或其他 GUI 实例。
4. 在 `tools` 目录启动程序：

   ```powershell
   python esp_csi_tool.py
   ```

5. 先填写匿名 `participant_id`、`room_id` 和 `receiver_id`。正式采集不要使用姓名、学号或联系方式。

## 2. 标准操作顺序

### 2.1 连接接收端和 Wi-Fi

1. 在**设备命令 - 串口连接**中选择或输入 `COMx`，点击**连接**。状态应从“未连接”变为已连接，运行日志应出现设备启动或命令回显。
2. 在**Wi-Fi 接入点（路由器 / ESP32 SoftAP）**中填写 SSID 和密码。
3. 选择触发方式。默认选择 `router_ping`；需要较高 CSI 到达率时，选择 `null_data`。
4. 点击该区域的**连接**。勾选“自动连接”时，程序会在下次启动后尝试复用保存的 SSID、密码和触发方式。
5. 等待**接收信息**中的字段和 **RSSI** 白线开始更新，再观察 **subcarrier amplitude** 曲线。三者至少有一项持续变化才说明 CSI 正在到达。

如果切换了路由器和 ESP32 SoftAP，只需改 SSID/密码并重新点击 Wi-Fi **连接**；接收端不需要为了这次切换重新刷写固件。

### 2.2 选择触发方式

| 方式 | 使用场景 | 结果与代价 |
| --- | --- | --- |
| `router_ping` | 默认模式；普通路由器或 ESP32 SoftAP 都可用 | 接收端发送 ICMP Ping，以常规网络流量触发 CSI。兼容性较好、网络行为直观；实际帧率受接入点响应和网络状态影响。 |
| `null_data` | 需要较高 CSI 到达率、并接受额外 Wi-Fi 控制流量 | 接收端主动发送 802.11 Null Data 帧并采集对端 ACK 相关 CSI。帧率通常更高，但会增加信道占用；CSI 的主要触发链路与普通业务 Ping 不同。 |

`null_data` 是当前接收端固件的运行时命令，不要求在每次打开 Python GUI 前重新刷写接收端，也不要求修改普通路由器或 SoftAP 发射端固件。实验 session 内不得混用两种触发方式；切换方式后新建 session，并重新采集空房和静止人员参考。

### 2.3 保存一个 trial

1. 在**采集控制与实验标签**中选择动作，确认人员、地点和接收设备标签正确。
2. 设置**每次等待**、**采集时长**和**采集次数**。等待倒计时内只准备动作；采集倒计时开始后再执行动作。
3. 若本次需要物理层分析，勾选“保存复数 I/Q”，并选择校准角色。常规动作采集使用 `activity`；空房或静止参考按现场手册执行。
4. 点击**开始**。一次窗口只完成一次动作，倒计时结束前保持动作完成后的状态。
5. 采集结束后检查运行日志没有解析错误，并按现场手册核对 CSV、`.meta.json` 和 `session_manifest.csv`。

**清空数据**只清空当前程序内的显示/缓冲数据，不能代替对已生成文件的质量检查。

## 3. 主界面与各区域用途

顶部的**原始数据**和**雷达模型**是显示开关：

- 关闭**原始数据**：隐藏设备命令、CSI 幅度、RSSI、日志和接收信息区域；接收线程仍可继续运行。
- 关闭**雷达模型**：整个 Radar model 区域（包括标题、校准、状态预测、雷达曲线和统计区域）一起隐藏；独立的 Collection 区域仍保留，CSI 接收和原始数据采集不会停止。

### 3.1 Raw data（原始数据）

| 区域 | 作用 | 正常现象与检查方式 |
| --- | --- | --- |
| 设备命令 | 串口连接、Wi-Fi SSID/密码、触发方式、自动连接和调试命令 | 连接后日志出现设备回显；切换 AP 后重新连接。自定义命令仅用于诊断或已知固件命令。 |
| subcarrier amplitude | 显示选取的 CSI 子载波幅度随时间的变化 | 多条曲线会随环境和人员动作改变。它显示幅度，不显示原始 I/Q 或绝对距离。 |
| 波形滤波 | 对显示缓冲做中值处理和低通滤波 | 打开后曲线更平滑，但会增加延迟和 CPU 负担；排查实时性或原始突变时可关闭。 |
| RSSI | 显示每个 CSI 帧携带的接收信号强度 | 白线通常为负 dBm，数值越接近 0 一般信号越强。RSSI 不能替代子载波 CSI。 |
| 运行日志 | 显示串口日志、连接状态、命令回显和解析异常 | 无 CSI 时先看此处是否有 Wi-Fi 认证失败、端口断开或格式错误。 |
| 接收信息 | 显示当前 CSI 帧的 MAC、RSSI、速率、信号模式、MCS、带宽、信道和 CSI 长度等帧头字段 | 字段持续更新说明收到了可解析的 CSI 帧；它不是发射端吞吐量或丢包统计。 |

### 3.2 雷达模型

| 区域 | 作用 | 使用要点 |
| --- | --- | --- |
| 环境校准 | 在无人环境下让雷达模型建立环境参考 | 设置延迟和持续时间；开始后保持房间无人。勾选“追加校准”只在已有校准基础上补充数据。 |
| 状态预测 | 配置有人/移动判定阈值，并显示模型输出 | “有人灵敏度”和“移动灵敏度”影响判定阈值；“异常值数量”控制缓冲窗口的异常判断。修改后点击**应用配置**。 |
| 雷达特征图 | 显示 `wander`、`jitter` 及各自阈值 | 用来观察模型内部特征是否越过阈值。数值不是速度、加速度或人体距离的物理标定值。图标题显示当前房间/人员状态。 |
| 显示数据表 | 显示房间与人员特征的 value、threshold、max、min、mean、std | 仅用于诊断特征和阈值；打开后增加表格刷新开销。 |
| 统计信息 | 按分钟、小时或天汇总模型判定出的移动记录 | 绿色柱是所选时间粒度下的移动计数。状态记录表是房间/人员状态的切换历史，不是原始 CSI 帧列表。 |

雷达模型输出用于在线观察和调试，不应替代正式跌倒检测数据集的离线标注、质量审计或模型评估。

### 3.3 采集控制与实验标签

这个区域以独立的 **Collection** 标题显示，不属于 Radar model。它不受“雷达模型”显示开关影响，用于把当前 CSI 流保存为可追溯的 trial。

- **人员标签（participant_id）**：匿名参与者编号，例如 `P001`。
- **地点标签（room_id）**：房间或场景编号，例如 `R01`、`LAB-A`。
- **设备标签（receiver_id）**：接收端编号，例如 `ESP32-RX-01`。
- **采集动作（Activity）**：单独占一整行，动作下拉框使用该行剩余宽度，便于完整显示较长标签。所选值写入本次 trial 的机器标签；新主实验使用现场手册中冻结的标签，不要把 GUI 旧兼容选项随意改名。
- **每次等待 / 采集时长 / 采集次数**：决定一次或多次 trial 的时间窗口；同一 session 内保持一致。
- **保存复数 I/Q / 校准角色**：控制物理层复数数据和参考数据的记录角色；正式研究采集应按现场手册设置。

## 4. 曲线颜色图例

### 4.1 CSI 与 RSSI

| 颜色 | 曲线 | 含义 |
| --- | --- | --- |
| 红色渐变 | 前半段被显示的有效 CSI 子载波 | 每条线对应一个不同的子载波索引。颜色深浅只用于区分曲线。 |
| 绿色渐变 | 后半段被显示的有效 CSI 子载波 | 与红色组共同构成当前 LLTF 幅度显示；默认每隔 5 个原始子载波选取一条，共 12 条。 |
| 白色 | RSSI | 当前 CSI 帧的接收信号强度。 |

红、绿的颜色不表示距离、动作类别、信号质量、正负幅度或人体状态。`subcarrier amplitude` 的图例数字是被显示的曲线索引，实际取样间隔为 5 个原始子载波。

### 4.2 雷达与统计

| 颜色 | 曲线或图形 | 含义 |
| --- | --- | --- |
| 蓝色 | `wander` | 雷达模型的第一条内部特征曲线。 |
| 绿色 | `jitter` | 雷达模型的第二条内部特征曲线。 |
| 黄色 | `wander` threshold | `wander` 的当前判定阈值。 |
| 品红色 | `jitter` threshold | `jitter` 的当前判定阈值。 |
| 绿色柱 | 统计图 | 所选时间粒度内累计的移动判定次数。 |

当特征越过对应阈值，模型可能改变房间或人员状态；是否改变还受模型缓冲和异常值配置影响，不能只凭某一时刻的单个交叉下结论。

## 5. 为什么曲线动画不够丝滑

 GUI 把数据接收和绘图分开处理，避免每收到一帧就立即重绘造成界面失去响应。当前版本还限制绘图窗口长度，并缓存滤波器系数：

- Raw CSI、RSSI 和接收信息每 **100 ms** 批量刷新一次，理论上约 **10 次/秒**。
- 雷达特征图和数据表每 **100 ms** 刷新一次，理论上约 **10 次/秒**。
- Raw CSI 的一次刷新最多绘制最近 **250 个点**，而不是每次重绘完整的 500 点缓冲；采集缓冲和保存文件仍保留完整数据。
- 滤波器系数只在界面初始化时计算，显示刷新不再重复设计 Butterworth 滤波器；帧头表只更新当前帧的一行。

因此即使 `null_data` 每秒到达更多 CSI，屏幕也会以定时器节奏批量跳动。开启**波形滤波**时，程序还会在 GUI 线程执行中值处理和 Butterworth 低通滤波；曲线会平滑，但绘制可能更慢。`router_ping` 的到达率还取决于接入点是否及时响应 Ping，低流量时会出现更明显的停顿。

推荐排查顺序：

1. 看**接收信息**和日志是否持续更新，先区分“无线 CSI 未到达”和“绘图刷新较慢”。
2. 为实时观察关闭**波形滤波**，关闭“显示数据表”，并保持 Raw CSI 区可见。当前版本已将 Raw CSI 显示提高到约 10 FPS；关闭滤波后响应通常更快。
3. 若实验允许较高 Wi-Fi 控制流量，使用 `null_data`；若做默认兼容流程，保留 `router_ping`。
4. 降低电脑其他负载，避免串口监视器与 GUI 同时占用同一端口。

## 6. 常见问题

### 6.1 已连接但没有任何 CSI 曲线

依次检查 COM 端口状态、运行日志、SSID/密码、接入点信道和距离。确认**接收信息**是否更新；若完全不更新，问题通常在串口、Wi-Fi 关联或发射源，而不是绘图颜色或滤波。

### 6.2 关闭雷达模型后，能否继续采集？

可以。关闭的是雷达显示、校准、预测和统计区；CSI 接收、Raw data 区和底部采集控制继续工作。关闭雷达模型适合仅做原始 CSI 采集，或为较小屏幕腾出空间。

### 6.3 普通路由器和 ESP32 SoftAP 是否要换接收端固件？

不需要。接收端在 GUI 中改 SSID、密码并重新连接即可。SoftAP 需要配置为可接受 STA 连接并响应接收端流量；具体烧录与参数见[ESP32-S3 SoftAP CSI 指南](../ESP32S3_SOFTAP_CSI_GUIDE_CN.md)。

### 6.4 什么时候需要重新刷写接收端？

只有更换接收端固件版本、修改其编译期配置或固件损坏时才需要。日常在 GUI 内切换路由器/SoftAP、`router_ping`/`null_data`、实验标签和采集参数不需要重新刷写。

## 采集参数单位

- **Tx_Rx_Dis（米）**：发射端与接收端之间的直线距离，单位为 `m`。开始采集前必须填写大于 0 的值；该值会写入 `session_manifest.csv` 和每个记录的 `.meta.json`。
- **每次等待、采集时长**：单位为秒（`s`），分别表示动作前等待时间和单次 CSI 记录时长。
- **采集次数**：单位为次，是当前动作需要重复记录的次数。
- **发送间隔**：若在实验配置中设置，单位为毫秒（`ms`）；它是触发请求间隔，不等于实际 CSI 到达频率。
- **信道、带宽、MCS、RSSI**：属于无线参数或接收测量值，不使用长度/时间单位；信道和 MCS 是编号，带宽以设备报告的枚举值表示，RSSI 通常以 dBm 表示。
- **有人灵敏度、移动灵敏度、阈值**：是模型的无量纲参数，不是米、秒或 dB。

Tx_Rx_Dis 应按发射端天线与接收端天线之间的直线距离测量；更换设备位置或距离时，应新建 `session_id`。

## 默认启动状态

- 界面默认使用 English，并打开“Radar model”；需要仅采集原始 CSI 时，可以取消勾选“Radar model”。
- “Auto connect”默认关闭。启动界面后不会自动向 Wi-Fi 接入点发起连接；确认 SSID、密码和触发方式后，手动点击“Connect”。
- 这两个选项只改变界面启动和连接行为，不会改变已保存的 CSI 数据格式。

## 界面布局与串口刷新

- Collection 是带独立标题的采集界面。人员、地点、设备标签分别分行，Activity 单独占一行，较长标签仍能完整查看。
- 主显示区左侧为 Raw data，右侧为 Collection，默认各占一半宽度；可拖动中间分隔条调整比例。
- Radar model 位于 Raw data/Collection 下方。取消顶部的 Radar model 复选框后，整个区域及其标题同时隐藏，不影响 Collection。
- 串口区域的 **Refresh** 会重新扫描可用 COM 端口；已输入或已选择的端口会尽量保留。
- SSID 和密码输入框已加宽；密码仍按 Wi-Fi 接入点要求填写，输入内容不会因为布局过窄而被截断。
