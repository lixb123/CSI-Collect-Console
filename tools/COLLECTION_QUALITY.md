# 采集前与采集后检查

当前路由器采集默认使用 `router_ping`。Null Data 仍可用于连接诊断，但正式采集默认拦截；只有重新验证目标 AP 的 CSI 接收后，才应在实验配置中启用 `allow_null_data_collection`。

## 开始一次新采集

1. 重启采集工具，连接串口和 Wi-Fi。目标 MAC 自动使用本次 `Connected to ... (bssid: ...)` 日志核验的 AP，不使用扫描结果或最后一个 CSI 帧推测。没有核验记录时重新连接 Wi-Fi。
2. 点击“已连接 AP”可恢复正确目标。曾使用错误 MAC 的 session 请新建编号，保留旧数据及其原标签，不覆盖。
3. 确认界面目标 AP 帧率达到阈值，模式稳定至少 3 秒。默认目标帧率下限 50 Hz、间断上限 100 ms，可在配置中调整；这些是初始质量标准，不保证动作识别效果。
4. 采集同站位 60 秒静止人员基线。只有同 session、同来源、模式、采样配置、摆位和质量策略的合格基线可复用。旧版本没有条件指纹的基线需重采。
5. 每个动作建议至少 3 次；固定路线、起止位置、速度范围及 Tx/Rx 位置，保留准备间隔。动作中途移动设备、改变房间或位置标签时重新建立 session 和基线。

## 数据与质量

- `log/<session>_<time>/csi_data.csv`：完整接收流，保留来源 MAC、I/Q、增益、MCS、带宽、设备时间等原有字段；不进行预览滤波。
- 动作 CSV：默认只保存已核验目标 MAC，保留其所有 PHY 类型；不插值、不消除增益、不低通。
- `.meta.json` 与 `session_manifest.csv`：记录来源筛除数量、原始流路径、目标帧率、间隔 P95/最大值、长间断数量、时间戳异常、主 PHY 占比及该子流最大间隔、队列丢样和基线条件指纹。
- `fail` / `needs_retake=true`：低帧率、超过间断阈值、帧覆盖不足、队列丢样、断连、重启等，应补采；不删除失败原始数据。
- `warn`：例如 PHY 类型变化，但目标链路连续性仍符合阈值。必须核查分组后数据；不能直接当成稳定的单一 PHY 序列。现有训练导出工具仍仅默认接受 `pass`，不会自动放宽训练数据标准。
- 零队列丢样不等于零无线丢包；包序号缺口在筛选来源后也不能直接当作目标丢包率。

## 预览与性能

CSI 每 100 ms 批量送往界面；界面队列满时只丢预览批次，原始/目标文件继续保存。重要质量提示保留待发送。文件每 250 ms 刷新，动作结束时 flush/fsync。突然断电仍可能损失未持久化部分，不承诺零数据损失。

预览仅显示已连接 AP；滤波开关只作用于预览。每次切换 AP 清空旧曲线。原始与归一化特征应在分析时并列使用：归一化不是物理增益校准，也可能去掉有用的动作幅度信息。

## 本次验证范围

自动化测试覆盖来源核验、显示队列满时串口完整写盘、低帧率、间断、时间戳回绕/异常、基线条件变更与 GUI 来源绑定。回放现场 8 段日志，4 段 Null Data 和约 1 秒间断的 Ping 段被标记失败。未刷固件；修改后尚未进行新的真人动作端到端测试。
